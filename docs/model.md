# Модель риска оттока

Модель прозрачная: каждый признак даёт число от 0 до 1, итоговый score — взвешенное среднее этих чисел в баллах от 0 до 100. Веса, пороги и горизонты меняются на вкладке «Модель» (или через `PATCH /api/v1/model/settings`) и сразу пересчитывают все оценки.

Код: `backend/app/scoring/` — `context.py` (общие величины), `features/` (по файлу на признак), `engine.py` (score и уровни), `money.py` (деньги).

## Общие величины

| Величина | Как считается |
|---|---|
| `as_of` | Момент оценки. Режим `snapshot` (по умолчанию): `capturedAt` снимка, а если его нет — самая поздняя дата `createdAt`/`performedAt` в данных. Режим `now`: текущее время на момент пересчёта. Режим `fixed`: дата из настроек |
| Длина периода оплаты | hour = 1/24, week = 7, month = 30, quarter_year = 91, half_year = 182, year = 365 суток |
| Живые услуги | статусы `active`, `suspended`, `prolong_wait` |
| Ушедшие услуги | статусы `deleted`, `blocked` |
| `available` | `balance` + `bonusBalance`, если бонус `unlocked`. `withdrawBalance` не прибавляется: он часть `balance` |
| `daily_burn` | Σ `price / длина_периода` по живым услугам аккаунта, в центах за сутки |
| `days_left` | (`expiresAt` − `as_of`) в сутках, для истёкших услуг отрицательный |

Все деньги хранятся и считаются в целых центах. В евро они переводятся только в ответах API и в интерфейсе.

## Признаки

| Ключ | Уровень | Когда применим | Значение v ∈ [0, 1] | Вес |
|---|---|---|---|---|
| `expiry_proximity` | услуга | active, suspended | `clamp(1 − days_left / horizon_days)`; истёкшая услуга: 1 | 20 |
| `autoprolong_off_near_expiry` | услуга | active, suspended | 1, если автопродление выключено и `days_left ≤ horizon_days` | 25 |
| `funds_deficit` | аккаунт | `daily_burn > 0` | `1 − min(1, runway / horizon_days)`, `runway = available / daily_burn` | 25 |
| `prolong_wait_state` | услуга | prolong_wait | денег меньше цены: 1; хватает: `0,6 + 0,4 · clamp(просрочка / 5 суток)` | 25 |
| `suspended_paying` | услуга | suspended | константа `suspended_value` (0,4) | 5 |
| `withdraw_leak` | аккаунт | `balance > 0` | `withdrawBalance / balance` | 5 |
| `bonus_dependency` | аккаунт | бонус unlocked и > 0 | `bonusBalance / (balance + bonusBalance)` | 5 |
| `unperformed_tx_share` | аккаунт | есть транзакции | доля `not_performed` | 5 |
| `billing_anomaly` | услуга | prolong_wait, автопродление включено, `available ≥ price` | 1 | 10 |

Признак уровня «аккаунт» участвует в оценке каждой живой услуги этого аккаунта. Признак с весом 0 не участвует в расчёте.

## Score и уровни

```
service_score  = 100 · Σ(wᵢ · vᵢ) / Σ(wᵢ)            по применимым признакам услуги
customer_score = α · max(service_score) + (1 − α) · mean(service_score)      α = 0,7
level: score < 35 → low;  35 ≤ score < 65 → medium;  score ≥ 65 → high
loyalty = 100 − score
```

Особые состояния клиента вместо уровня риска:

- `churned` — живых услуг нет, но есть `deleted`/`blocked`. Score не считается; клиент попадает в потерянную выручку и в список для win-back.
- `no_data` — услуг нет совсем или ни один признак не применим к живым услугам.

Причины риска — три признака с наибольшим вкладом `wᵢ · vᵢ` по самой рисковой услуге клиента. Вклад показывается в баллах score (`100 · wᵢ · vᵢ / Σwᵢ`), объяснение — готовой фразой с суммами в евро.

## Денежная оценка

```
P(churn | score)        = 1 / (1 + exp(−k · (score − s₀)))        k = 0,08, s₀ = 60
value(услуга)           = price · horizon_money_days / длина_периода          horizon_money_days = 30
coverage(аккаунт)       = min(1, available / Σ value живых услуг)
expected_loss(услуга)   = value · P(service_score) · (1 − balance_shield · coverage)     balance_shield = 0,5
```

| Показатель | Формула |
|---|---|
| Выручка под риском | Σ value живых услуг у клиентов уровней medium и high |
| Ожидаемые потери | Σ expected_loss по всем услугам с оценкой |
| Можно предотвратить | Σ по аккаунтам `max(0, Σ value продлеваемых услуг − available)` — сколько клиентам не хватает, чтобы сохранить услуги. Продлеваемые: живые услуги, истекающие в пределах `horizon_days`, и услуги `prolong_wait`, истёкшие не больше 5 суток назад (их ещё можно оплатить до удаления) |
| Потерянная выручка / мес. | Σ `price · 30 / длина_периода` по ушедшим услугам клиентов `churned` |
| Доля почасовых | доля выручки под риском от услуг с `paymentTerm = hour` |

Доля почасовых услуг выводится рядом, потому что `value` почасовой услуги за 30 дней в 720 раз больше её цены и может незаметно доминировать в сумме.

## Качество данных

Предупреждения не влияют на score и показываются в карточке клиента:

- `prolong_wait` дольше 5 суток после `expiresAt` (по правилам платформы услуга уже должна быть удалена);
- `active`/`suspended` с `expiresAt` раньше `as_of`;
- `prolong_wait` при включённом автопродлении и достаточных средствах.

## График оттока

Все три линии в одной единице — **число услуг** по дням:

- **Факт** — услуги, перешедшие в `deleted`/`blocked` между двумя загруженными снимками (`app.service_status_events`). Переход засчитывается, только если это та же услуга: совпадают id, владелец, имя и дата создания. Поэтому переключение между наборами official и demo не создаёт ложных событий.
- **Оценка даты** — удалённые услуги, датированные `expiresAt + 5 суток` (правило удаления после prolong_wait).
- **Прогноз** — для живых услуг, истекающих в ближайшие 30 дней, сумма `P(churn)` по дням окончания: ожидаемое число потерянных услуг.

## Обоснование коэффициентов

- **Веса 25** у признаков, которые прямо ведут к потере услуги: нет денег, выключено автопродление у истекающей услуги, услуга уже ждёт продления. **20** у близости окончания: сама по себе она не означает уход. **10** у аномалии продления: это скорее риск недовольства, чем немедленной потери. **5** у слабых косвенных сигналов (вывод, бонусы, неуспешные транзакции, приостановка): в синтетических данных их связь с оттоком не проверена.
- **α = 0,7**: клиента чаще всего теряют из-за одной проблемной услуги, поэтому максимум важнее среднего, но среднее отличает клиента с одной проблемной услугой из пяти от клиента, у которого проблемы везде.
- **Пороги 35 / 65** делят шкалу на три примерно равные части с небольшим сдвигом вниз, чтобы «средний» уровень ловил ранние сигналы.
- **Логистическая кривая** с серединой 60 и k = 0,08: при score 35 вероятность около 12 %, при 60 — 50 %, при 85 — около 88 %. Кривая монотонна и ограничена, поэтому деньги не уходят в ноль или в бесконечность на краях шкалы.
- **balance_shield = 0,5**: деньги на счёте снижают ожидаемые потери, но не до нуля — клиент с балансом тоже может уйти.
- **Горизонт риска 7 суток, денежный — 30 суток**: неделя соответствует циклу реакции (успеть напомнить и предложить продление), месяц — привычный горизонт выручки.

Все коэффициенты — экспертные допущения для синтетических данных. На реальных данных их стоит откалибровать по истории оттока (например, подобрать k и s₀ логистической регрессией по фактическим уходам).
